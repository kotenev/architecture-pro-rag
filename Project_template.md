# Задание 1. Исследование моделей и инфраструктуры для RAG-бота QuantumForge Software

## 1. Сравнение LLM-моделей (локальные Hugging Face vs облачные OpenAI / YandexGPT)

### 1.1. Локальные модели (Hugging Face)

Варианты: 

#### Llama 2/3, Mistral, Falcon, MPT

Преимущества:
- полный контроль над данными (критично для SOC 2);
- нет ограничений по токенам;
- предсказуемые затраты после развертывания;
- низкая латентность при правильной настройке;
- возможность fine-tuning под домен.

Недостатки:
- высокие начальные инфраструктурные затраты;
- требуется экспертиза для развертывания и поддержки;
- качество ответов часто уступает топовым облачным моделям;
- необходимость GPU (A100/H100) для приемлемой скорости.

Метрики:
- скорость: 20-50 токенов/сек (с GPU);
- качество: 70-85% от GPT-4 (зависит от модели);
- стоимость владения: €3,000-8,000/мес (инфраструктура);
- время развертывания: 2-4 недели.

#### OpenAI (GPT-4, GPT-3.5-turbo):

Преимущества:
- лучшее качество ответов на рынке;
- быстрое развертывание (часы, не недели);
- минимальная DevOps нагрузка;
- регулярные обновления модели.

Недостатки:
- данные передаются третьей стороне (риск для SOC 2);
- непредсказуемые затраты при масштабировании;
- зависимость от внешнего провайдера;
- возможные проблемы с GDPR.

Метрики:
- скорость: 40-100 токенов/сек;
- качество: эталонное (GPT-4);
- стоимость: €0.03-0.12 за 1K токенов (GPT-4);
- ожидаемые затраты: €1,500-4,000/мес при 100 сотрудниках.

#### YandexGPT:

Преимущества:
- соответствие российским требованиям (если актуально);
- конкурентная цена;
- поддержка русского языка.

Недостатки:
- ограниченная документация на английском;
- меньшее сообщество и экосистема;
- неоптимально для финско-эстонской компании.

## 2. Сравнение моделей эмбеддингов

### 2.1 Локальные (Sentence-Transformers)

Топ модели:
- all-MiniLM-L6-v2 (22M параметров, 384 измерений);
- all-mpnet-base-v2 (110M параметров, 768 измерений);
- bge-base-en-v1.5 (110M параметров, 768 измерений).

Преимущества:
- бесплатно после развертывания;
- полный контроль над данными;
- быстрая генерация (~1000 текстов/сек на CPU);
- простое развертывание.

Недостатки:
- качество поиска уступает лучшим облачным;
- ограниченная поддержка многоязычности;
- требуется fine-tuning для специфичных доменов.

Метрики для all-mpnet-base-v2:
- скорость индексации: 18000 документов за ~30 минут (CPU);
- качество поиска: NDCG@10 ≈ 0.55-0.60;
- стоимость: €0 (только CPU);
- размер модели: 420MB.

### 2.2 Облачные (OpenAI Embeddings)

Модель: text-embedding-3-large (3072 измерений)

Преимущества:
- высочайшее качество поиска;
- отличная многоязычность;
- нет необходимости в инфраструктуре.

Недостатки:
- стоимость растет с объемом данных;
- зависимость от API;
- передача данных в облако.

Метрики:
- скорость: ограничена rate limits API;
- качество: NDCG@10 ≈ 0.65-0.70;
- стоимость: $0.13 за 1M токенов;
- для 18K документов (однократно): ~€15-30;
- для 400 новых страниц/месяц: ~€5-10/мес.

## 3. Сравнение векторных баз данных

### 3.1 FAISS (Facebook AI Similarity Search)

Преимущества:
- экстремально быстрый поиск (миллисекунды);
- отличная оптимизация памяти (индексы IVF, PQ);
- работает локально (безопасность);
- бесплатно и open-source;
- проверено в production (Meta, OpenAI).

Недостатки:
- только in-memory или файловая система;
- нет встроенной персистентности;
- отсутствует multi-tenancy;
- требуется самостоятельная реализация CRUD;
- нет нативной фильтрации по метаданным.

Метрики:
- скорость поиска: <10ms для 1M векторов;
- скорость индексации: ~5000 векторов/сек;
- использование памяти: ~1.2GB для 100K векторов (768 dim);
- сложность внедрения: средняя (нужна обертка);
- стоимость: 0.

### 3.2 ChromaDB

Преимущества:
- удобный API (out-of-the-box persistence);
- встроенная фильтрация по метаданным;
- нативная интеграция с LangChain;
- поддержка multi-tenancy;
- встроенное управление коллекциями;
- может работать как сервер (client-server mode).

Недостатки:
- медленнее FAISS при больших масштабах;
- больше overhead по памяти;
- относительно молодой проект (меньше battle-tested).

Метрики:
- скорость поиска: ~50-100ms для 1M векторов;
- скорость индексации: ~2000 векторов/сек;
- использование памяти: ~2GB для 100K векторов (768 dim);
- сложность внедрения: низкая (ready-to-use);
- стоимость: €0 (self-hosted).

### 3.3 Альтернативы (краткий обзор)

Qdrant:
- лучший баланс функций и производительности;
- Rust (высокая скорость);
- отличная фильтрация.

Pinecone:
- managed cloud (SaaS);
- высокая цена;
- проблемы с GDPR.

Weaviate:
- полнофункциональная vector DB;
- GraphQL API;
- избыточен для начального MVP.

## Предлагаемые варианты решений

### Вариант 1: "Полностью локальный" (Privacy-First)

Компоненты:
- LLM: Llama 3 70B (квантизованная) или Mistral 7B;
- embeddings: bge-base-en-v1.5;
- Vector DB: FAISS;
- инфраструктура: Self-hosted (AWS/Azure EU регион).

Преимущества:
- максимальная безопасность данных;
- полное соответствие SOC 2 и GDPR;
- предсказуемые затраты;
- полный контроль.

Недостатки:
- высокие начальные инвестиции;
- требуется ML/DevOps экспертиза;
- более долгое внедрение (2-3 месяца);
- качество ответов ниже топовых облачных моделей.

Стоимость:
- разработка: €40,000-60,000;
- инфраструктура: €4,000-6,000/мес;
- поддержка: 1 FTE ML Engineer (€6,000/мес);
- total year 1: €170,000-230,000.

Окупаемость: 18-24 месяца

### Вариант 2: "Облачный" (Time-to-Market)

Компоненты:
- LLM: GPT-4-turbo (OpenAI);
- Embeddings: text-embedding-3-large (OpenAI);
- Vector DB: ChromaDB (self-hosted);
- инфраструктура: Minimal backend (AWS/Azure).

Преимущества:
- быстрое внедрение (2-4 недели);
- лучшее качество ответов;
- минимальные DevOps требования;
- pay-as-you-grow модель.

Недостатки:
- данные передаются OpenAI;
- сложности с SOC 2 compliance;
- непредсказуемый рост затрат;
- vendor lock-in.

Стоимость:
- разработка: €15,000-25,000;
- API costs: €2,000-4,000/мес (100 пользователей);
- инфраструктура: €400-800/мес;
- поддержка: 0.5 FTE (€3,000/мес);
- Total Year 1: €60,000-90,000.

Окупаемость: 6-9 месяцев

### Вариант 3: "Гибридный" (Рекомендуемый)

Компоненты:
- LLM: GPT-4-turbo (для продакшна) + Llama 3 8B (для dev/test);
- Embeddings: bge-large-en-v1.5 (локально);
- Vector DB: ChromaDB (self-hosted);
- инфраструктура: Hybrid (embeddings локально, LLM облачно).

Преимущества:
- Баланс между безопасностью и качеством;
- Данные индексируются локально (compliance);
- Лучшее качество ответов (GPT-4);
- Умеренные затраты;
- Возможность миграции на полностью локальное решение;
- Быстрое внедрение (4-6 недель).

Недостатки:
- запросы все равно идут в OpenAI;
- требуется data anonymization pipeline.

Стоимость:
- разработка: €25,000-35,000;
- API costs: €2,000-3,500/мес;
- инфраструктура: €600-1,200/мес;
- поддержка: 0.7 FTE (€4,000/мес);
- Total Year 1: €85,000-120,000.

Окупаемость: 9-12 месяцев

Путь миграции:
1. Phase 1 (месяцы 1-3): MVP с GPT-4 + ChromaDB;
2. Phase 2 (месяцы 4-6): Добавление PII detection/masking;
3. Phase 3 (месяцы 7-12): Оценка локальных LLM, постепенная миграция критичных use cases.

Стоимость:
- разработка: €60,000-90,000

## 6. Итоговые рекомендации

### Рекомендуемое решение: Вариант 3 (Гибридный)

Обоснование:

1. Соответствие бизнес-целям:
    - быстрый time-to-value (4-6 недель vs 2-3 месяца);
    - сокращение затрат на поиск информации на 60-70% в первые 6 месяцев;
    - масштабируемость под рост компании.

2. Баланс безопасности и производительности:
    - векторная индексация происходит локально (данные не покидают периметр);
    - только запросы пользователей и релевантные фрагменты передаются в OpenAI;
    - можно внедрить PII detection/masking для критичных данных.

3. Технические преимущества:
    - ChromaDB: простая интеграция, хорошая производительность (достаточная для 18K документов);
    - bge-large-en-v1.5: отличное качество эмбеддингов без облачных затрат;
    - GPT-4: лучшее качество ответов для критичных use cases.

4. Финансовая эффективность:
    - ROI: 9-12 месяцев;
    - экономия времени: ~4 часа/неделю * 100 инженеров * €50/час = €20,000/месяц;
    - затраты: €8,500-10,700/месяц после внедрения;
    - чистая выгода: €9,300-11,500/месяц.

5. Путь миграции:
    - можно начать быстро, получить value;
    - постепенно мигрировать на локальные LLM по мере созревания технологий;
    - избежать vendor lock-in благодаря LangChain abstraction.

## Заключение

Для QuantumForge Software оптимальным решением является гибридный подход с локальными эмбеддингами (bge-large-en-v1.5), векторной базой ChromaDB и облачной LLM (GPT-4). Это обеспечивает:
- быстрое внедрение и получение бизнес-ценности;
- разумный баланс между безопасностью и качеством;
- прогнозируемый ROI в 9-12 месяцев;
- гибкость для будущей миграции на полностью локальное решение.

ChromaDB выбрана как векторная база благодаря простоте использования, достаточной производительности для текущего масштаба и нативной интеграции с экосистемой LangChain, что критично для быстрого MVP.
